# 数据与安全规则

## 契约

- `packages/contracts`中的Zod Schema是API和学习包协议唯一契约。
- TypeScript类型从Schema推导，不重复手写同结构接口。
- 移动端、后台、API入口和学习包构建工具共同使用契约。
- NestJS通过轻量校验Pipe调用Schema，不维护第二套装饰器DTO。
- Prisma模型不得直接作为API响应。
- ID使用字符串，金额使用整数分，时间使用UTC ISO字符串。
- 可选字段使用省略；只有主动清空时使用 `null`。
- API错误包含错误码、用户可读信息和请求追踪ID。
- 破坏性字段变化必须升级API或学习包协议版本。
- 契约修改必须通过所有消费者的契约测试。

## 数据库访问

- SQLite只通过移动端数据访问层使用。
- PostgreSQL只通过API仓库层使用。
- 页面、组件、Controller和用例不得直接执行SQL或调用Prisma。
- 外部输入先验证，再进入数据库操作。
- 原生SQL必须参数化；只有ORM无法正确表达或有明确性能理由时使用，并写明原因与测试。
- 表结构只通过版本化迁移修改；正式环境禁用自动结构同步。
- 数据库唯一约束、外键和检查约束守住最终数据底线。
- 支付发放使用权、学习状态与待同步记录、主设备切换必须使用事务。
- 数据库事务内不得等待外部网络请求。

## 删除与正式数据

- 订单、支付、退款、`pack_access`和审计日志禁止物理删除。
- 账号注销时去标识化账号并按规则删除学习数据，依法保留必要交易记录。
- 验证码、过期会话、同步待办和缓存可按明确条件物理删除。
- 禁止无条件 `DELETE`和 `UPDATE`。
- 正式数据库批量修改先预览影响行数、备份并取得明确确认。
- AI不得自行执行正式环境不可逆迁移或数据修复。

## 鉴权与支付

- 所有API输入和第三方回调在边界完成结构校验。
- 服务端从已验证会话取得 `userId`，不相信客户端传入的用户ID。
- 登录状态和学习包使用权由服务端判断。
- 每次学习包下载检查 `pack_access`。
- 支付金额、商品ID和订单状态由服务端数据库确定。
- 支付回调必须验签、校验商户与金额并保证幂等。
- 后台接口同时检查后台会话和操作权限。
- 安全检查失败时默认拒绝，不能先放行后补查。

## 学习包与文件

- 安装前校验签名、哈希、协议版本、文件大小和内部路径。
- 下载到临时文件，完整检查后原子切换。
- 学习包不得携带或触发可执行代码。
- 禁止路径穿越、任意文件覆盖和无上限解压。

## 密钥与密码

- 禁止自创加密、签名、随机令牌和密码哈希算法。
- `.env`、密钥、证书和完整令牌不得进入Git、日志、错误或UI。
- 手机会话令牌只进入Android Keystore。
- 学习包签名私钥不得进入App和运行期API。
- 管理员密码使用成熟密码哈希。
- 进入移动端的任何变量都视为可公开读取。

## 错误与日志

- 找不到内容、验证码过期、无使用权、支付待确认等预期失败使用有类型的错误码。
- 数据库断开、文件损坏、SDK异常和不变量破坏等意外故障抛出异常。
- 只在用例、模块和API边界使用统一结果类型，不要求每个小函数包装 `Result`。
- UI文案与内部错误分离。
- 错误码使用简单英文，如 `PACK_NOT_FOUND`、`PAYMENT_PENDING`。

`FORBIDDEN`：空 `catch`；捕获后只记录并假装成功；统一返回 `false`或 `null`隐藏错误；支付或同步返回假成功；记录手机号、验证码、令牌、密钥或敏感支付内容；对非幂等写操作无条件重试；`eval`；`dangerouslySetInnerHTML`；未校验动态SQL。

鉴权、支付、学习包使用权和包校验代码修改后必须进行独立安全审查。
