# 测试与审查规则

## 测试

- 新增或修改业务行为必须同时修改测试。
- 缺陷修复先写能够稳定复现问题的失败测试。
- SM-2、学习任务、支付状态、学习包使用权、同步版本和学习包校验优先测试后实现。
- 单元测试与源码同目录，例如 `save-progress.ts`和 `save-progress.test.ts`。
- 跨数据库、API和支付适配器的测试放在 `tests/integration`。
- 测试名称可以使用简洁中文。
- 时间测试使用固定时钟，不依赖真实当前时间。
- 自动测试不得访问真实短信、微信支付和正式对象存储。
- PostgreSQL关键流程使用真实测试数据库，不用内存假数据库替代。
- 外部服务只在适配器边界模拟，禁止Mock掉全部内部逻辑。
- 不用全局覆盖率数字替代有效分支测试；支付、使用权、同步和状态迁移覆盖全部有效分支。
- UI快照只用于稳定小组件，不替代行为断言。

`FORBIDDEN`：

- 删除失败测试让CI通过。
- 降低断言或覆盖要求掩盖问题。
- 提交 `.only`或 `.skip`。
- 等待真实时间。
- 循环重跑不稳定测试。
- 返回假成功数据通过演示。

## 审查等级

- `P0`：支付错误、权限绕过、密钥泄露或不可恢复数据损坏；立即停止发布。
- `P1`：主要功能错误、同步覆盖、崩溃或架构边界破坏；禁止合并。
- `P2`：维护性、性能或边界问题；当前任务修复。
- `P3`：命名、可读性和轻微改进；修复或说明。

每条审查意见包含：

- 具体文件和行号。
- 可复现或可推导的问题。
- 真实影响。
- 最小修复方向。

禁止空泛评价。没有发现问题时明确说明，并列出未覆盖测试和残余风险。

审查顺序：

1. 是否存在可以删除的无用代码或过度抽象。
2. 是否违反架构与依赖边界。
3. 是否存在数据、安全、支付或同步错误。
4. 是否缺少有效测试或虚报验证。
5. 文件、函数、命名和注释是否清晰。

## FORBIDDEN升级

规则升级为 `FORBIDDEN`需同时满足：

1. AI很可能反复犯。
2. 可能静默失败或造成严重损失。
3. 已在真实审查中出现至少两次，或属于一次即不可接受的安全问题。

只满足部分条件时使用 `REQUIRED`或 `RECOMMENDED`。同类严重错误重复出现后，同时更新规范和自动检查。

## 自动检查

项目根命令：

```text
pnpm format:check
pnpm lint
pnpm typecheck
pnpm test
pnpm test:contract
pnpm test:integration
pnpm check:deps
pnpm check:secrets
pnpm build
pnpm check
```

TypeScript开启严格模式、未检查索引提示、精确可选字段、未知catch变量和显式重写。

自动拦截多种锁文件、循环和越层依赖、`any`、无用变量、调试 `console.log`、超限参数/嵌套/复杂度/源码行数、`.only`、`.skip`、无编号TODO、疑似密钥与证书，以及格式、类型、测试或构建失败。

职责、命名、抽象程度和注释价值由规范与审查判断。日常运行快速 `pnpm check`；数据库集成测试和完整Android构建在CI或发布前运行。
